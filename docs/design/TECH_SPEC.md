# ZeroSQL v2: технический контракт

Этот документ обязателен для всех, кто пишет мир, кейсы, стор и экраны. Сюжет, персонажи и заложенные факты описаны в `GAME_DESIGN.md`, визуальные правила — в `UI_ART_DIRECTION.md`.

## 1. Слои и правило фасада

```
UI (src/app, src/components)  →  стор (src/stores/game-store.ts)  →  фасад @/engine  →  внутренности src/engine/*
```

- Код вне `src/engine` импортирует движок **только** из `@/engine`. Исключение — тесты.
- Компоненты не импортируют движок. Данные они получают из стора или через пропсы.
- Контент лежит в JSON (`src/data/**`). Типы контента описаны в `src/types/case.ts` и `src/types/story.ts`.

## 2. Раскладка контента

```
src/data/
  characters.json            CharacterDef[]  — канонический каст (id = папка портретов)
  handbook.json              HandbookEntry[] — справочник, статьи открываются делами (CaseDef.concepts)
  secrets.json               SecretDef[]     — тайники/пасхалки
  achievements.json          AchievementDef[]
  cases/
    index.ts                 собирает все дела (импорт case.json + script.json), экспортирует cases: CaseDef[]
    case-00-<slug>/case.json CaseDef без scenes
    case-00-<slug>/script.json { "scenes": Scene[] }
    case-01-<slug>/…
```

**Идентификаторы**
- Дело: `case-NN-<slug>`. Порядковый номер `NN` равен `order`.
- Короткий префикс дела: `cNN`, например `c03`.
- Реплика: `cNN.<sceneId>.<nnn>`, например `c03.interrogation.007`. Это же имя аудиофайла: `public/voice/c03.interrogation.007.mp3`. Служебные реплики вне дел: `note.` (записи Ирины), `ep.` (эпилог), `bark.` (реплики на действия), `hint.` (наводки, сцена `cNN_<id задачи>`), `sys.` (МИРА). Общее выражение: `^(c\d{2}|note|ep|bark|hint|sys)\.[a-z0-9_-]+\.\d{3}$` (меняется в `LINE_ID_RE` вместе с контентом). Интерлюдия — `case-11-chernovik`, финал — `case-12-pervoe-solntse`.
- Сцена: `[a-z0-9_-]+`, уникальна в пределах дела.
- Улика: `ev.cNN.<slug>`, уникальна в пределах сезона.
- Задача: `[a-z0-9_-]+`, уникальна в пределах дела: `p1`…`p5` в прологе, `o5_1`, `o10_2b` в делах, `i1`…`i4` в интерлюдии. Те же id пишутся в `query_log.objective_id`.
- Персонаж: `snake_case` латиницей. Портреты: `public/portraits/<id>/<emotion>.webp`.

Всю структурную целостность проверяет `validateCaseContent` / `validateSeasonContent` из `@/engine`. Тест сезона обязан проходить.

## 3. Мир (генерируемая база данных)

```
src/engine/world/
  rng.ts        детерминированный ГСЧ (Rng, fork) + форматы 'YYYY-MM-DD HH:MM:SS' и 'YYYY-MM-DD'
  pools.ts      ФИО, госномера, телефоны, uniqueFactory(reserved)
  schema.ts     DDL всех таблиц мира (+ query_log)
  context.ts    WorldContext: rng-форки, аллокаторы id, резервы, исключения для шума
  generate.ts   generateWorld(db, seed = WORLD_SEED)
  plants/
    index.ts    реестр: core → c00 … cNN → eggs (порядок фиксирован)
    core.ts     сквозные факты сезона: каст как жители, их телефоны/машины/логины, предыстория
    c00.ts …    факты конкретного дела
    eggs.ts     пасхалки
  noise/…       генераторы фонового шума по таблицам
  facts.ts      экспорт ключевых констант для тестов (имена, номера, время)
```

**Порядок генерации**
1. Схема.
2. Посадки (plants) в порядке реестра. Каждая посадка:
   - вставляет свои строки (с явными id, если важно);
   - резервирует ключи, которые шум не должен повторить: `ctx.reserve(kind, value)`, например номер машины или телефон;
   - регистрирует исключения для шума: `ctx.exclude(table, predicate)`. Это нужно для утверждений «ровно N строк» и «только он был у камеры в 02:10–02:40».
3. Шум по таблицам с учётом резервов и исключений.
4. Пост-обработка: индексы, `ANALYZE`.

**Требования**
- Детерминизм: одно зерно `WORLD_SEED` даёт одинаковую базу у всех игроков и во всех тестах.
- Объём: примерно 20–60 тыс. строк. Генерация в Node занимает не больше 1,5 с, в браузере это ощутимо быстрее загрузки шрифтов. Вставка идёт через подготовленные выражения внутри одной транзакции.
- Шум реалистичен: суточные ритмы, будни и выходные, районы, повторяющиеся маршруты, опечатки там, где люди вводят руками.
- Шум не создаёт ложных ответов. За этим следят исключения и тесты фактов.
- Даты хранятся строками по одному правилу (оно же в `GAME_DESIGN.md`, разд. 8.1): столбцы даты-времени — `'YYYY-MM-DD HH:MM:SS'`, секунды всегда записаны; столбцы-даты — `'YYYY-MM-DD'`, их полный список — в разд. 8.1 библии. Время местное, UTC+3. Исключения, которые учат игрока: `gs_comms_2015.ts_unix` (unix-время UTC) и `arch16_registry.reg_date` (`'ДД.ММ.ГГГГ'`). Литералы в эталонах пишутся с той же точностью, что у столбца. Игровые часы (`game_now()`) тоже отдают `'YYYY-MM-DD HH:MM:SS'`; в `CaseDef.date` секунды можно опустить, тогда они равны `00`. `clock.ts` и `rng.ts` переходят на этот формат.
- Таблица `query_log` — часть мира. Генератор может предзаполнить её чужими запросами. Строки игрока движок дописывает через `logQueryResult` **после** проверки задач и тайников.

**Фасад**: `initWorld(): Promise<{ db, schema, foreignKeys }>` (v2) и `createWorldDatabase()` для тестов. Пока стор v1 жив, функция `initEngine()` (v1) остаётся. После перехода на v2 удаляются v1-миссии, `schema.ts`/`seed.ts` v1 и `mission-runner.ts`.

## 4. Как писать задачи (валидация)

Проверяется **результат**, а не текст SQL. Засчитываться должен любой корректный запрос.

- Предпочтительные правила: `column_values` (нужные значения в столбце, с любыми алиасами), `rows_match` (строки эталона; лишние столбцы допустимы; `ordered: true` для заданий на ORDER BY), `cell_value` (одно найденное число или значение).
- `row_count`, `contains_columns` и `requires_column` годятся только как дополнение в `compound`. Сами по себе они слишком слабые или слишком строгие.
- `not` нужен, чтобы отсечь ложный след («Орлова в результате быть не должно»).
- `solution` (эталонный SQL) обязателен у каждой задачи. Он должен использовать только таблицы из `tables` дела и только концепции SQL, уже пройденные к этому делу.
- Подсказки: 3–4 уровня (намёк → концепция → шаблон → почти решение), каждая звучит голосом персонажа (`by`).
- Ответы протокола (`answer`) должны встречаться в результатах эталонных решений задач дела. Иначе игрок не сможет их «увидеть»: по умолчанию `requireSeen: true`.

## 5. Тесты дела (обязательны)

`src/__tests__/cases/cNN.test.ts`:
1. Мир генерируется один раз (`beforeAll`), время генерации под контролем.
2. `validateCaseContent` возвращает пустой список.
3. Для каждой задачи:
   - `solution` проходит через `checkCaseProgress` по порядку;
   - есть хотя бы одна альтернативная корректная формулировка (другие алиасы, JOIN вместо подзапроса), и она тоже проходит;
   - есть хотя бы две правдоподобные ошибки (забытый фильтр, `= NULL`, лишний JOIN-дубль, ложный след), и они **не** проходят;
   - `solution` пропускает table-guard с `tables` этого дела.
4. Каждый `answer` протокола находится через `scanSeenOptions` в результатах решений. Верные ответы протокола подтверждаются, неверные — нет.
5. Факты, на которых держится сюжет дела, проверяются явными SQL-запросами к миру: «ровно 1 машина», «единственный, кто…».
6. Тайники и пасхалки не меняют ни одного ответа.

## 6. Стор и экраны (v2)

- `src/stores/game-store.ts` переписывается под v2. Состояние: текущее дело, игровое время, выполненные задачи, раскрытые подсказки (по задачам), полученные улики, увиденные варианты протокола, подтверждённые пропуски, попытки сверки, флаги выборов, найденные тайники, статистика и очки по делам, достижения, настройки (громкость, скорость текста, автопрокрутка). Сохранение — localStorage через `persist` с версией схемы и миграцией.
- База не сохраняется: мир генерируется заново. Строки игрока в `query_log` восстанавливаются из сохранённой истории.
- Маршруты: `/` (титул), `/play` (доска дел и стол расследования), `/archive` (свободный режим после сезона), `/lab` (витрина компонентов, только dev).
- До перехода стора на v2: `/` — запуск (предупреждение → холодное открытие → окно входа «Зеркала»), `/game` — стол «Зеркала» на текущем сторе и прежних делах; `/lab?scene=desk|protocol|wall|dialogue|title|coldopen` — собранные сцены для приёмки (UI_ART_DIRECTION, раздел 14). Таблица результата в `/lab` — настоящий вывод SQLite через фасад (`app/lab/world.ts`).
- **Квота запросов** (`CaseDef.queryBudget`, необязательна): тратит её только выполненный запрос. Ошибка SQLite, «ОТКАЗАНО» (засекреченная таблица) и попытка записи квоту не списывают, подвал результата пишет «квота не списана». Терминал показывает квоту, только если у дела задан `queryBudget`. Shift+Enter — перевод строки, запрос не выполняет; выполняет Ctrl+Enter (Cmd+Enter).

- `npx tsc --noEmit`, `npm run lint`, `npm run test:run`, `npm run build` должны проходить зелёными перед каждым коммитом.
- Сообщения коммитов на английском. Тексты в игре и комментарии в коде — на русском, в стиле кодовой базы.
