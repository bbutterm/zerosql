# ZeroSQL: Полынья — Тайники в данных

**Сезон 1 «Полярная ночь»** · документ к разд. 8.3, 8.4, 10.2–10.4 библии (`GAME_DESIGN.md`) · статус: КАНОН для пасхалок

Тайник — необязательная находка в данных мира: имя, микросюжет, отсылка, шутка или трогательная деталь, от которой сюжет не зависит и которую видно только тому, кто копает глубже, чем нужно для задачи. Находку ловит правило `SecretDef.trigger` по результату любого запроса игрока (`src/engine/secrets.ts`, `checkSecrets`). За находку игрок получает короткую записку в коллекции «Тайники» и копит скрытые достижения.

Определения тайников лежат в `src/data/secrets.json` (`SecretDef[]`, тип — `src/types/case.ts`). Строки мира сажает `src/engine/world/plants/eggs.ts`. Этот документ — единственный источник правды для обоих файлов: строки, id, тексты записок и правила ниже совпадают с JSON дословно (записки и триггеры в разделах 3.x вставлены из `secrets.json`).

Уже существующая пасхалка «житель Исаев, 1900-01-01» (разд. 8.3) — не тайник: её разбирает висяк side-02. Тайники её не трогают и не повторяют её шутку про «дату по умолчанию».

## 1. Принципы

1. **Сюжет не зависит.** Ни одна задача, протокол, предсказание, якорь диктофона, условие cron-задания, допрос, обвинение или реплика не опирается на тайник. Если выключить `eggs.ts`, каждый эталон даёт тот же засчитанный результат (тест 8.5).
2. **Только раскопкой.** Строка тайника не попадает в результат ни одного эталона задачи (включая ★) и ни одного «естественного» запроса по задаче: первого взгляда `SELECT * … LIMIT 10/20`, окна задачи, сортировки «свежие сверху» с небольшим LIMIT. Даты и значения подобраны так, чтобы строка лежала в стороне от окон задач (раздел 3, «Коллизии»).
3. **Порог фокуса.** Триггер, кроме значения, требует сфокусированный результат: `row_count` не больше порога (30–300 строк — по размеру таблицы). Полный просмотр таблицы (`SELECT * FROM t` без условий) тайник не открывает. Ориентир — порог реестра увиденного (разд. 6.4): результат до 200 строк движок читает целиком.
4. **Точное значение.** Триггер ловит значение, которого в шуме нет и не будет: генератор резервирует ключи и исключает совпадения (раздел 2). Используются только правила по результату: `cell_value`, `contains_substring`, `column_values`, `row_count`, `compound`, `any_of`. Правила `seen`, `pin`, `slot`, `custom`, `table_state` в тайниках запрещены.
5. **Правдоподобие в мире.** Строка выглядит как обычная запись: формат и словари шума (статусы, отделения, коды сот, маршруты, улицы из `catalog.ts`). Шутка — в содержимом. Четвёртую стену ломает только подпись в DDL (№ 1), и она лежит вне данных.
6. **Не трогать посаженное (разд. 8.4).** Явные id — вне посаженных; уникальные ключи зарезервированы; ни одна дата не лежит на границе окна задачи; нет слов-ловушек (`ЕДЕТ`, «Щит», «372», «37», «Сайгак», `Береговая, 4`, код 7741) и «сюжетных» минут (03:12, 21:47, 21:56, 22:40, 22:52, 23:05, 23:08, 23:10, 23:34, 23:41, 23:52, 02:14, 02:22, 02:47:19, 12:58, 13:00).
7. **Без реальных людей и брендов.** Отсылки — через имена-переклички, даты и цитаты; названий реальных компаний, продуктов и живых людей нет. Марки, банки и магазины — из вымышленных словарей мира.
8. **Тон 18+ с теплом.** Смешно или трогательно; над погибшими и жертвами сюжета не шутим. Записки звучат голосами героев с их тиками (Нина — «голубчик», Даша — «Так. Стоп.», «клюёт», Тоха — «хе», «короч», Ратников — «Ну-с», «коллега», МИРА — ровно, «Найдено…: ноль», Ирина — «Ладно. Дальше.»). К игроку — без родовых форм (линтер реплик, разд. 6.14 п. 7).
9. **Записка не раскрывает будущее.** Текст записки опирается только на строки, видимые в самое раннее дело находки, и не подсказывает ответы задач и твисты.
10. **Неизменны при новой смене (NG+).** Тайники — посадки: их значения и id фиксированы, как у посаженных фактов; пересевается только фон.

## 2. Общие правила посадки (для всех тайников)

1. **Порядок.** `eggs` сажается последним в `PLANT_REGISTRY` (после `c12`) и до шума. Явные id тайников перечислены в `facts.ts` (`EGG_IDS`, раздел 6); посадки дел их не берут, CI проверяет пересечения (`ctx.insert` и так падает на занятом id).
2. **Плавающие строки.** Строки упорядоченных и «временных» таблиц (`incidents`, `query_log`, `statements`, `transactions`, `messenger_events`, `purchases`, `intercom_events`, `plate_reads`, `transit_taps`, `hospital_admissions`, `evidence_registry`, `gs_comms_2015`, `grant_requests`, `company_owners`) вставляются без id, с `orderAt` — шум выдаёт им id по времени (`fillOrdered`, `flushByTime`, `flushOrderedFree`, `generateGsComms`). Поэтому `LIMIT 10` без ORDER BY их не показывает. **Нужно доработать `generateGrantRequests`**: сейчас он пишет только шум через `nextId` и не забирает `ctx.takeDeferred("grant_requests")` (это нужно и посадке c09 с заявкой Ратникова).
3. **Жители-пасхалки.** У каждого отчество не NULL; у каждого есть прописка (иначе он станет седьмым «мёртвым» в side-06); `created_at` не раньше даты рождения и не позже `2026-11-19 18:00:00` (самая новая карточка — по-прежнему Кравец 4301, 2026-11-20 02:22:00); шум не делает им дублей (side-04) и не берёт их в пулы событий: заявители вызовов, плательщики, участники переписки, шаблоны `query_log` (`noise/logs.ts`), легальные правки `audit_log`, пациенты шумовой больницы, владельцы машин и телефонов. Для этого `eggs.ts` экспортирует `EGG_PERSON_IDS`, а `noise/people.ts` исключает эти id из `st.adults`/`st.people` так же, как `CAST_SHORT` — их короткие ФИО.
4. **Снимок 2016 года.** Жители-пасхалки с `created_at` до 30.09.2016 попадают в `arch16_persons` дословно (у Мухина и Фунтова `special_marks` одинаковы — NULL), остальные туда не попадают. Новых расхождений в 10.4 (27 через `IS NOT`, 21 через `!=`) и в контрольном запросе 11.3 нет.
5. **Адреса-пасхалки** — без хвостовых пробелов, улицы и номера домов из `catalog.ts` (кроме «3-я Строителей», № 14). Шум не прописывает к ним случайных жильцов и не создаёт по ним событий домофона: `ctx.exclude("registrations", …)`, `ctx.exclude("intercom_events", …)` по `EGG_ADDRESS_IDS`.
6. **Резервы ключей** (`ctx.reserve`): `phone`, `plate`, `account`, `login`, `badge`, `card_no`, `inn`, `company_name`, `case_id`, `kusp:2026`, `act_no`, `zags:person`, `gs_ext`, `staff:officer` — перечень по тайникам в разделе 3, сводно — в разделе 6.
7. **Исключения для шума** (`ctx.exclude`), чтобы находка была единственной: тексты-триггеры ни в одной строке шума; `amount = -1` в `transactions`; `special_marks = 'NULL'` в `persons`; `deregistered_at < registered_at` в `vehicles`; одинаковые `street|house|apt` в `addresses` (шум и так уникален по `addressKey`); у номеров шума не больше 7 разных сот за час в `messenger_events`; у `payer_person_id` 3071 нет других покупок сигарет; номер `М088АК` без OCR-гомоглифов.
8. **Практика и сводки.** Генераторы «Ночных вызовов», «Сводки дня» и мини-задач утренней сводки (разд. 6.3, 10.4) не берут строки тайников в шаблоны и эталоны: иначе тайник находился бы решением задачи. `eggs.ts` экспортирует `EGG_ROW_KEYS` (таблица → предикат строки).
9. **Данные не склеиваются в SQL.** Движок нигде не склеивает SQL из значений данных (перепроверка карточек, якоря, протокол, `evidence_registry`, экспорт в CSV, практика) — только параметры. Это проверяет регрессионный тест на Бобби (№ 8, тест 8.7).
10. **Версия генератора.** Посадка пасхалок меняет байты мира: поднять `WORLD_GENERATOR_VERSION` (ключ кеша IndexedDB).

## 3. Тайники

### 3.1. «Подпись на полях» — `secret.ddl_signature`

*Тон:* гиковский · *голос записки:* авторы · *`SecretDef.tables`:* не задано

**Отсылка.** Подпись авторов в исходниках и слоган сезона «Каждая строка — это чей-то вечер». Заменяет семя «строка-подпись с id 0».

**Где и когда.** `sqlite_master` открыта всегда (разд. 6.14, п. 4). Самое раннее — пролог. `tables` не задано.

**Посадка.** Не данные, а текст DDL. В `src/engine/world/schema.ts` у `incidents` появляется необязательное поле `TableDef.ddlComment`, и `tableDdl()` выводит его отдельной строкой перед закрывающей скобкой:

```sql
CREATE TABLE incidents (
  …
  y_m REAL
  -- Если ты это читаешь, ты копаешь глубже, чем просили. Каждая строка здесь — чей-то вечер. Спасибо, что тратишь на них свой. Те, кто строил этот город.
)
```

SQLite хранит текст `CREATE` в `sqlite_master.sql` дословно, вместе с комментарием (проверено на sql.js 1.14.2, SQLite 3.49.1).

**Как найти.** Из любопытства к устройству базы: `SELECT * FROM sqlite_master;` или `SELECT sql FROM sqlite_master WHERE name = 'incidents';`. Ни одной задаче `sqlite_master` не нужна: крючок `cron_jobs` (М6) — это только имя таблицы.
Образец: `SELECT name, sql FROM sqlite_master WHERE name = 'incidents';`

**Триггер.**
```json
{"type": "contains_substring", "column": "sql", "substring": "копаешь глубже, чем просили"}
```

**Записка.**

> Под последним столбцом таблицы вызовов есть строка, которую не покажет ни один грид: SQLite хранит текст CREATE целиком, вместе с пометками на полях. Её оставили те, кто строил этот город. Каждая строка здесь — чей-то вечер. Спасибо, что тратишь на них свой.

**Коллизии.** Данные таблиц не меняются; P.1, P.2 и CI «запрос Нины → id 1–10» не задеты. Панель схемы читает `PRAGMA table_info` (`database.ts`) — комментарий в ней не виден, то есть он не подсказывается интерфейсом. Комментарий стоит на своей строке: в одной строке с последним столбцом `--` съел бы скобку. В тексте нет `;` и кавычек — на случай разбиения DDL по `;`. Байты мира меняются — поднять `WORLD_GENERATOR_VERSION`. Тест, если он сравнивает `WORLD_SCHEMA_SQL` со снимком, обновить.

## 7. Реализация: `src/data/secrets.json` и `src/data/index.ts`

- `secrets.json` — массив из 22 `SecretDef` (`id`, `title`, `text`, `trigger`, `tables`). Порядок — как в сводке (по делу, где тайник находится раньше всего). Тексты записок — без разметки, кроме «ёлочек»; RichText не нужен.
- `tables` — таблицы, без доступа к которым тайник не найти (`checkSecrets` требует, чтобы были открыты **все**). У № 1 поле не задано: `sqlite_master` открыта всегда. Для тайников с несколькими путями указана таблица самого раннего пути (у «Януса» — `registrations`, Д6).
- `src/data/index.ts`: заменить заглушку `export const secrets: SecretDef[] = []` на импорт `secrets.json` через `records("secrets.json", secretsJson, ["id", "title", "text"])` — так же, как `achievements.json`.
- Стор: `checkSecrets(secrets, result, db, found, unlockedTables, ctx)` вызывается после проверки задач и до `logQueryResult` (TECH_SPEC, разд. 4); найденные id сохраняются в прогрессе; коллекция «Тайники» показывает найденные записки и, для ненайденных, подсказку «нужна таблица …» по `tables`.

## 8. Тесты

`src/__tests__/content/secrets.test.ts` (контент) и `src/__tests__/engine/world/eggs.test.ts` (мир). Все — на настоящем сгенерированном мире (`generateWorld`), часы — на потолке самого раннего дела находки, если не сказано иное.

1. **Форма JSON.** 22 записи; id уникальны и начинаются с `secret.`; у `compound`/`any_of` есть `successMessage`; типы правил только из списка принципа 4; `tables` — имена из `WORLD_TABLES`; в записках нет родовых форм, обращённых к игроку (общий линтер реплик). Пересечение `EGG_IDS` с id посадок дел пусто.
2. **Каждый тайник находится.** Для каждого id — образцовый запрос из раздела 3 («Образец»): `checkSecrets(secrets, result, db, ∅, tablesOf(earliestCase))` возвращает ровно `[id]` (не больше одного тайника на образец). Альтернативные пути из «Как найти» — тоже.
3. **Самое раннее дело.** На таблицах и часах дела, предшествующего самому раннему, образцовый запрос тайник не находит (таблица закрыта или строка за горизонтом); на самом раннем — находит. Для «Служебного романа» — Д7 (потолок 23:30) нет, Д8 — да; для № 21 и № 22 — И (потолок 00:30) нет, Д11 — да.
4. **Нет ложных срабатываний.** Для каждой таблицы: `SELECT * FROM t`, `SELECT * FROM t LIMIT 10`, `SELECT * FROM t LIMIT 20`, `SELECT * FROM t ORDER BY <столбец горизонта> DESC LIMIT 20` → `[]` (кроме `sqlite_master`: её полный просмотр и есть раскопка № 1). Плюс выборка «опасных соседей»: `SELECT datetime(0, 'unixepoch', '+3 hours')`, `SELECT * FROM phones`, `SELECT * FROM persons WHERE id IN (1965, 1975, 1976, 1985, 1931)`, `SELECT * FROM plate_reads WHERE plate = 'М088АК'`, `SELECT * FROM purchases WHERE item LIKE '%сигарет%'` → `[]`.
5. **Эталоны не задеты.** Для каждого дела и каждой задачи (включая ★ и условные): результат `solution` на старте и на потолке часов не открывает ни одного тайника (`checkSecrets` → `[]`), а валидация задачи проходит на мире с пасхалками и на мире с `eggs: false` (опция генератора только для тестов). Ответы протоколов находятся в результатах эталонов по-прежнему; предсказания (`PredictionDef.answer`) совпадают с числом строк.
6. **Инварианты библии.** Кравец 4301 — самая новая карточка; Исаев — самый старый житель; side-06 — ровно 6 «мёртвых душ» плюс Кравец; 10.4 — 27 через `IS NOT` и 21 через `!=`; ★Д10 `GLOB '*[A-Z]*'` — 17; 8.3 — один Лыков; `GROUP BY street, house, apt HAVING COUNT(*) > 1` по `addresses` — одна строка «3-я Строителей»; самое длинное `full_name` — у Бобби; `amount = -1` — 29 строк, все пасхальные; `special_marks = 'NULL'` — один 404; `deregistered_at < registered_at` — один 'М088АК'; P.1 (`SELECT * FROM incidents LIMIT 10`) — id 1–10.
7. **Бобби и безопасность.** Строку `persons` 327 можно приколоть, перепроверить (`recheckCard`), выгрузить в CSV, найти поиском обвинения; запрос с экранированным литералом `'Роберт''); DROP TABLE persons;--'` проходит guard и возвращает 1 строку; неэкранированный — отказ guard «только чтение» (второй оператор `DROP`), таблица цела; `logQueryResult` с этим именем в тексте запроса пишет строку без ошибок.
8. **Детерминизм.** Два прогона генератора с одним сидом дают одинаковые id строк тайников; при NG+ (другой сид фона) значения строк тайников и их триггеры прежние.
